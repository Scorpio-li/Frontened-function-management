# CSS 效果模块 Spec

> 需求编号：`css-effects-module`
> 状态：已批准（实施中）

## 1. 问题与目标

### 1.1 问题

项目缺少一个集中展示和管理可复用前端视觉效果的模块。团队成员写过的 CSS 样式、CSS 动画、ECharts 数据可视化等效果散落在各项目中，没有统一的预览、分类与代码复制入口，导致：

- 重复造轮子
- 不知道团队已有的效果资产
- 复制代码时需要翻项目找源文件

### 1.2 目标

在现有插件化架构下新增 **CSS 效果平台模块**（独立包 `packages/css-effect`，包名 `@repo/css-effect`），作为前端视觉效果的资产库。**它是与「功能管理」平级的平台模块，不是 FeatureRegistry 中的功能包**：

- **分类管理页**（`/css-effect`）：只展示分类列表，管理员可新增、编辑、删除分类
- **分类效果页**（`/css-effect/category/:categoryId`）：展示该分类下的效果卡片，管理员可在该分类下新增效果、编辑、删除、批量转移
- **代码查看**：点击效果卡片弹出代码对话框，展示完整预览与源码分区，支持一键复制（不再有独立的效果详情页）
- **删除分类安全策略**：删除分类时其下效果自动归为「未分类」，不丢失任何效果数据

### 1.3 用户与角色

| 角色   | 权限                                      |
| ------ | ----------------------------------------- |
| admin  | 完整 CRUD：分类管理 + 效果管理 + 批量转移 |
| viewer | 只读：浏览分类、看效果卡片、复制代码      |

### 1.4 非目标

- 不做效果编辑器（用户无法在平台内拖拽创建效果），只能录入 HTML/CSS/JS 代码
- 不做效果在线调试/热更新
- 不做效果评价、收藏、下载统计
- 不做版本管理或历史快照
- 不考虑分类嵌套（仅支持扁平分类）
- 不做 viewer 的提交审核流（若未来开放提交，直接 admin 维护）

| B-06 | viewer 看不到分类/效果的增删改按钮，只能浏览与复制代码                                       | rule |

## 3. 数据模型

### 3.1 EffectCategory

```ts
interface EffectCategory {
  id: string; // randomUUID()
  name: string; // 1-32 字符，唯一
  description?: string; // 可选，≤ 200 字符
  createdAt: string; // ISO
  updatedAt: string; // ISO
}
```

### 3.2 CssEffect

```ts
type EffectType = 'css' | 'animation' | 'echarts';

interface CssEffect {
  id: string;
  categoryId: string | null; // null = 未分类
  name: string; // 1-64 字符
  description?: string;
  effectType: EffectType;
  tags: string[]; // 可选标签
  html?: string; // HTML 片段
  css?: string; // CSS 片段
  js?: string; // JS 片段（可选）
  echartsOption?: unknown; // ECharts 配置 JSON（仅 echarts 类型）
  preview?: string; // 预览缩略图 base64 或留空用实时预览
  createdAt: string;
  updatedAt: string;
}
```

**说明**：`categoryId` 为 `null` 时表示「未分类」——删除分类后，该分类下所有效果的 `categoryId` 被置为 `null`。

## 4. API 契约

统一前缀 `/api`，所有接口需登录。

| 方法   | 路径                                  | 权限   | 说明                                                                                  |
| ------ | ------------------------------------- | ------ | ------------------------------------------------------------------------------------- |
| GET    | `/api/css-effects/categories`         | 已登录 | 列出所有分类                                                                          |
| POST   | `/api/css-effects/categories`         | admin  | 创建分类                                                                              |
| PATCH  | `/api/css-effects/categories/:id`     | admin  | 更新分类                                                                              |
| DELETE | `/api/css-effects/categories/:id`     | admin  | 删除分类（效果归为未分类）                                                            |
| GET    | `/api/css-effects/effects`            | 已登录 | 列出效果，支持 `?categoryId=xxx`、`?categoryId=null`（未分类）、`?type=xxx`、`?q=xxx` |
| POST   | `/api/css-effects/effects`            | admin  | 创建效果                                                                              |
| PATCH  | `/api/css-effects/effects/:id`        | admin  | 更新效果                                                                              |
| DELETE | `/api/css-effects/effects/:id`        | admin  | 删除效果                                                                              |
| POST   | `/api/css-effects/effects/batch-move` | admin  | 批量转移 `{ effectIds: string[], targetCategoryId: string                             | null }` |

错误语义沿用 `@repo/contracts`：401/403/400/404/409/500。

## 5. 存储方案

**后端新增 `EffectStore`**，复用 `AccountStore` 模式：

- JSON 文件：`apps/server/data/css-effects.json`（已被 `.gitignore` 忽略）
- 原子写入：临时文件 + rename
- 写操作串行队列

文件结构：

```json
{
  "categories": [...EffectCategory],
  "effects": [...CssEffect]
}
```

**不在 `@repo/contracts` 中新增类型**：CSS 效果是纯业务模块，前后端各自维护类型。

## 6. 效果预览渲染策略

| 类型                | 渲染方式                                                                                            |
| ------------------- | --------------------------------------------------------------------------------------------------- |
| `css` / `animation` | 用 `<iframe sandbox="allow-scripts">` 内联渲染完整 HTML 文档（srcdoc），传入用户的 html + css + js  |
| `echarts`           | iframe 引入 echarts CDN + 用户 option JSON，挂载到容器                                              |
| 卡片缩略预览        | 渲染一个**尺寸受限的 iframe**（宽约 220px，高约 120px），只渲染 html + css，不执行 JS，以纯视觉展示 |

安全要点：

- iframe 设置 `sandbox="allow-scripts"`，不带 `allow-same-origin`，防止访问宿主 localStorage / Cookie
- iframe 使用 `srcdoc`，不传用户 URL，避免 XSS 窃取
- 卡片缩略预览不执行 JS（缩略展示），详情页才启用 `allow-scripts`

## 8. 依赖与约束

### 8.1 依赖

| 依赖                                                                                | 用途             | 版本        |
| ----------------------------------------------------------------------------------- | ---------------- | ----------- |
| 复用 `apps/server/src/store.ts` 的写队列 + 原子写入模式                             | EffectStore 实现 | 不新增      |
| 复用 `@repo/contracts` 的错误码与 sendError 模式                                    | API 错误处理     | 不新增      |
| 复用 `@repo/core` 的 Feature 契约、defineFeature、EventBus                          | 功能包注册       | 不新增      |
| ECharts CDN（iframe 内 `https://cdn.jsdelivr.net/npm/echarts/dist/echarts.min.js`） | echarts 类型预览 | 不进 bundle |

### 8.2 约束

1. **不得**修改 `@repo/core` 的 `Feature` / `FeatureRoute` 契约来支持嵌套路由——保持扁平路由列表。
2. **不得**修改侧边栏导航渲染逻辑（AppShell.tsx）来支持动态子菜单——分类切换在功能页面内部完成。
3. **不得**让功能包直接依赖 `apps/server` 的 EffectStore——只能通过 `/api/css-effects/*` 访问。
4. `css-effects.json` 不得提交到仓库（已在 `.gitignore` 中）。

### 8.3 假设

1. 效果总量预计 < 500 条，JSON 文件 < 2MB，无需引入数据库。
2. 单个效果的 html/css/js 片段都很短（几 KB 量级），不做富文本。
3. ECharts 依赖通过 CDN 加载，用户打开详情预览时需要能访问 jsdelivr CDN。

### 8.4 开放问题

| 问题                           | 决定                                                                                  |
| ------------------------------ | ------------------------------------------------------------------------------------- |
| 分类顺序由创建时间还是可拖拽？ | 创建时间升序。未来有需要再加排序字段。                                                |
| 效果搜索是否跨分类？           | 是。首页搜索框搜索全局。                                                              |
| 是否支持效果点赞？             | 不做，在非目标列表里。                                                                |
| echarts CDN 被墙怎么办？       | 可配置 fallback URL 或让用户把 echarts 放到 apps/web/public/echarts.js。P0 先用 CDN。 |

## 10. 需求变更记录

### 2026-11-20 第二版（平台模块化 + 目录重组）

用户提出的结构性调整，已同步到第 1~2、9 节：

1. **定位变更**：CSS 效果由「功能包」改为「与功能管理平级的平台模块」，不再注册进 `FeatureRegistry`，改由 `apps/web/src/platforms.ts` 注册，`AppShell` 渲染独立分组。
2. **目录重组**：所有 `feature-*` 功能包统一迁至 `packages/features/`；CSS 效果模块独立为 `packages/css-effect/`（包名 `@repo/css-effect`），不与 features 目录混放。
3. **信息架构变更**：
   - 分类管理页只显示分类列表（可增删改），不再混排效果卡片
   - 每个分类在侧边栏有对应子菜单，进入后展示该分类下的效果卡片，并可在该分类下新增效果代码
   - 删除「效果详情页」及其路由，改为分类页内点击卡片弹出代码查看对话框
4. **兼容性**：后端 `/api/css-effects/*` 接口与数据模型不变。
